# سامانه مدیریت اعضا و گروه‌های مستقل (فاز ۱)

سامانه فول‌استک، امن، ماژولار و راست‌چین (RTL) به زبان فارسی جهت مدیریت یکپارچه دو گروه مستقل سازمانی (گروه الف و گروه ب)، ثبت و ارزیابی فعالیت‌ها، پایش حضور و غیاب، رتبه‌بندی اعضا (سطوح ۱ تا ۵) و دفتر کل امتیازات.

---

## ۱. مشخصات معماری و فناوری‌های به‌کاررفته

- **بخش فرانت‌اند (Frontend):**
  - فریم‌ورک React 19 با تایپ‌اسکریپت (TypeScript)
  - استایل‌دهی مدرن با Tailwind CSS v4، متناسب با استانداردهای طراحی سازمان و زبان فارسی (فونت وزیرمتن - Vazirmatn)
  - رعایت دقیق قرارداد نوار بالا (Top Bar Contract) و سیاست پرهیز از المان‌های زائد (Anti-AI Slop)
  - پشتیبانی از Progressive Web App (PWA) با مانیفست استاندارد (`manifest.webmanifest`)
  - تعامل بصری ماشین‌حساب در صفحه ورود با پرسش ریاضی `4 × 6 =`

- **بخش بک‌اند و پایگاه داده (Backend & Database):**
  - فریم‌ورک Node.js + Express با روت‌های تفکیک‌شده در `server.ts`
  - ذخیره‌سازی پایدار و تراکنشی دیتابیس در فایل دیسک (`data/db.json`) با مکانیزم اتمیک و Mutex Lock
  - سیستم هش کلمه عبور با استفاده از الگوریتم استاندارد و مقاوم Scrypt همراه با Salt تصادفی ارزشمند (بدون ذخیره رمز خام)
  - سیستم کنترل نشست‌ها (Session Tokens) امن با انقضای ۲۴ ساعته
  - محافظت در برابر حملات جستجوی فراگیر (Brute-Force Rate Limiting) با قفل موقت ۱۵ دقیقه‌ای پس از ۵ تلاش ناموفق
  - الزام کاربران به تغییر رمز عبور در نخستین ورود (`mustChangePassword`)
  - ذخیره‌سازی محرمانه تصاویر پیوست در پوشه خصوصی دیسک (`data/uploads/`) و سرو از طریق روت اختصاصی احراز هویت شده

## ۲. ساختار نقش‌ها، سطوح دسترسی و انزوای گروه‌ها

سامانه بر اساس خط‌مشی **عدم پذیرش پیش‌فرض (Default-Deny Policy)** عمل می‌کند:

1. **مدیر ارشد (Super Admin):**
   - دسترسی کامل به کلیه تنظیمات، ماتریس مجوزهای نقش‌ها، کاربران هر دو گروه و لاگ‌های امنیتی.
2. **رهبر (Leader):**
   - دسترسی نظارتی و مدیریتی به هر دو گروه الف و ب در چارچوب اختیارات تعریف‌شده.
3. **فرمانده کل (Commander-in-Chief):**
   - دسترسی عملیاتی و پایش عملکرد به هر دو گروه الف و ب در چارچوب اختیارات.
4. **فرمانده گروه (Group Commander):**
   - دسترسی انحصاری و صرفاً به گروه سازمانی اختصاص‌یافته خود (گروه الف یا گروه ب). دسترسی به گروه دیگر در سرور مسدود است (خطای ۴۰۳).
5. **منشی گروه (Group Secretary):**
   - امور اداری و ثبت حضور و غیاب منحصراً برای گروه خود.
6. **عضو عادی (Regular Member):**
   - دسترسی صرفاً به کارتابل شخصی، گزارش فعالیت‌های خود، وضعیت حضور و امتیازات فردی. هرگونه ارتقای دسترسی در سمت سرور مسدود شده است.

### رتبه‌بندی اعضا (Member Ranks):
- سطوح ۱ تا ۵ پیاده‌سازی شده‌اند؛ سطح ۱ بالاترین رتبه و سطح ۵ رتبه پایه است.
- رتبه عضویت مستقل از نقش مدیریتی کاربری است و توسط مدیر ارشد در بخش مدیریت کاربران قابل تغییر است.

## ۳. حساب‌های کاربری تستی آماده (Synthetic Test Accounts)

جهت بررسی سریع و تست تمامی نقش‌ها و سناریوهای امنیتی، حساب‌های زیر به‌صورت پیش‌فرض در دیتابیس ایجاد شده‌اند:

| نقش کاربری | شماره تلفن (نام کاربری) | کلمه عبور پیش‌فرض | حوزه سازمانی | توضیحات تستی |
| :--- | :--- | :--- | :--- | :--- |
| **مدیر ارشد** | `09120000001` | `Admin@123456` | هر دو گروه | دسترسی به ماتریس مجوزها و نسخه پشتیبان |
| **رهبر** | `09120000002` | `Leader@123456` | هر دو گروه | نظارت بر فعالیت‌ها و گزارش‌های هر دو گروه |
| **فرمانده کل** | `09120000003` | `Chief@123456` | هر دو گروه | بررسی و ابلاغ مأموریت‌های سراسری |
| **فرمانده گروه الف** | `09120000010` | `CmdA@123456` | گروه الف (ذوالفقار) | عدم امکان دسترسی یا اصلاح گروه ب |
| **منشی گروه الف** | `09120000011` | `SecA@123456` | گروه الف (ذوالفقار) | ثبت حضور و غیاب جلسه هفتگی گروه الف |
| **عضو عادی گروه الف** | `09120000012` | `MemberA@123456` | گروه الف (ذوالفقار) | تست تغییر رمز اجباری در نخستین ورود |
| **فرمانده گروه ب** | `09120000020` | `CmdB@123456` | گروه ب (رعد) | عدم امکان دسترسی یا اصلاح گروه الف |
| **منشی گروه ب** | `09120000021` | `SecB@123456` | گروه ب (رعد) | ثبت امور اداری گروه ب |
| **عضو عادی گروه ب** | `09120000022` | `MemberB@123456` | گروه ب (رعد) | ثبت فعالیت، درخواست مرخصی با امتیاز |
| **حساب مسدودشده** | `09120000099` | `Disabled@123456` | - | تست امنیتی رد دسترسی کاربر غیرفعال |

## ۴. راه‌اندازی و اجرای پروژه

### پیش‌نیازها:
- Node.js نسخه 18 یا بالاتر
- npm

### گام‌های اجرا در محیط توسعه:
```bash
# نصب وابستگی‌ها
npm install

# اجرای سرور فول‌استک (Express + Vite روی پورت 3000)
npm run dev
```

سامانه بر روی آدرس `http://localhost:3000` در دسترس خواهد بود.

## ۵. اجرای آزمون‌های خودکار امنیتی (Automated Tests)

برای اطمینان از اعمال درست قواعد انزوای گروه‌ها و عدم دور زدن دسترسی‌ها، مجموعه تست‌های خودکار طراحی شده‌اند:

### روش ۱: اجرای مستقیم از طریق خط فرمان (CLI)
```bash
npm test
```

### روش ۲: اجرای زنده از داخل داشبورد سامانه
۱. با حساب کاربری مدیر ارشد (`09120000001`) وارد شوید.
۲. از منوی کناری به بخش «پشتیبان‌گیری و آزمون‌ها» بروید.
۳. دکمه «اجرای زنده تمام آزمون‌ها» را بفشارید.
نتایج اجرای تک تک آزمون‌ها به همراه مدت زمان پاسخگویی نمایش داده می‌شود.

### موارد مورد ارزیابی آزمون‌ها:
1. **رمزنگاری رمزها:** اطمینان از ذخیره نشدن پسورد خام و صحت‌سنجی Scrypt + Salt.
2. **مسدودسازی حساب‌های غیرفعال:** جلوگیری قطعی از ورود یا فراخوانی API توسط حساب‌های `disabled`.
3. **انزوای کامل گروه‌ها:** عدم امکان مشاهده یا دستکاری داده‌های گروه ب توسط فرمانده گروه الف.
4. **جلوگیری از ارتقای دسترسی عضو عادی:** مسدود بودن امکان تغییر نقش، اعطای امتیاز به خود یا خود‌تأییدی فعالیت‌ها.
5. **الزام تغییر رمز عبور در ورود اول:** قفل بودن مسیرهای API تا زمان تکمیل تغییر کلمه عبور.
6. **سلامت دفتر ثبت رویدادها (Audit Log):** ثبت کامل کنش‌ها همراه با جزئیات و شناسه عامل.

## ۶. نسخه پشتیبان و بازیابی پایگاه داده (Backup & Recovery)

- کلیه داده‌ها در مسیر `data/db.json` نگهداری می‌شوند.
- نسخه‌های پشتیبان تایم‌استمپ‌دار در پوشه `data/backups/` ذخیره می‌گردند.
- امکان دریافت فایل خروجی کامل JSON از طریق دکمه «دریافت خروجی JSON» در پنل سیستم فراهم است.
- در صورت نیاز به بازنشانی به وضعیت پیش‌فرض، گزینه «بازنشانی پایگاه داده (Reset to Seed)» در دسترس است.

## ۷. ریسک‌های امنیتی باقی‌مانده و اقدامات دستی برای فازهای بعدی

با توجه به این‌که این مرحله **فاز ۱ (Phase 1)** پروژه است، موارد زیر برای ارتقای امنیت در محیط عملیاتی واقعی (Production) پیشنهاد می‌شود:
1. **فعال‌سازی HTTPS / TLS در سرور نهایی:** کلیه ترافیک و توکن‌های نشست باید منحصراً از کانال امن HTTPS عبور داده شوند.
2. **سخت‌گیری کوکی‌های HTTP-Only با پرچم Secure و SameSite=Strict:** در صورت نیاز به مهاجرت کامل از Bearer Token به کوکی‌های امضاشده.
3. **اتصال به سامانه پیامکی امن (SMS OTP):** در فاز بعدی جهت احراز هویت دوعاملی (2FA) هنگام ورود یا تراکنش‌های حساس.
4. **سرویس آنتی‌ویروس / اسکن فایل پیوست:** اسکن فایل‌های تصویری آپلودشده قبل از ذخیره بر روی دیسک با ابزارهایی مانند ClamAV.
